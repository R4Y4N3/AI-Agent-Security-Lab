RESEARCH CONTRACT

Evidence before claims.

Question: Can task-scoped tool authorization contain prompt-injection effects while preserving legitimate task completion?

Two distinct experiments

Policy replay: Known proposals exercise the enforcement boundary. Replay outcomes are not measured model attack-success rates.

Live model: A local Ollama model chooses tools. Malicious content enters through a tool response, never a trusted system instruction. Only completed runs where the input was observed enter the relevant rate denominator.

What gets recorded

Case and source hashes, Git revision and dirty state, trial and seed, generation settings, observed tool effects, error/limit status, and model trajectories. The web runner also captures the installed model digest. Fresh random canaries are synthetic, and are not made reproducible from the model seed.

Safety and utility are separate

We report benign task completion, completion under attack, attack exposure, prohibited effects, and excluded runs. A blocked proposal is not evidence that the task succeeded. Unexposed and failed runs are not silently counted as resisted attacks.

Known limits

This is a small hand-authored corpus, not a representative benchmark. The single-process mock ledger is not a payment system. Policies are narrow allowlists, not a general prompt-injection detector. Model seeds are best-effort reproducibility controls, not a guarantee of identical inference across machines.
