Experiment notes

Question: Can task-scoped authorization contain prompt-injection effects while preserving legitimate task completion?

Replay and live-model runs

Policy replay: known proposals test the enforcement boundary. These are not measured LLM attack-success rates.

Live model: a local Ollama model chooses tools. Untrusted content arrives through a tool response, not the system instruction. Only completed runs where input was observed enter the relevant rate denominator.

Evidence

Reports include source and case hashes, Git revision and dirty state, trial and seed, generation settings, observed effects, errors, and model trajectories. The web runner also captures the installed model digest. Canaries are fresh synthetic values, not derived from the model seed.

Reading the outcomes

Benign completion, completion under attack, prohibited effects, exposure, and excluded runs are reported separately. Blocking a proposal does not mean the task succeeded. Unexposed or failed runs do not count as resisted attacks.

Limits

This is a small hand-authored corpus around one invoice workflow, not a representative benchmark. The mock ledger is not a payment system, and the policies are narrow allowlists, not a general injection detector. Seeds do not guarantee identical model inference across machines.
